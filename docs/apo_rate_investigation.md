# 「アポ0件」の調査記録と改善内容

2026-09-08〜09 の調査。フォーム営業からのアポが1件も出ていない件について、
原因の切り分けと修正を行った記録。

## 結論

**文面やターゲットの問題に到達する前に、システムが出していた数字がほぼすべて
実態と違っていた。** 到達・失敗・要確認・除外のどのバケットも、記録されていた
理由が原因を指していなかった。加えて、本文が空のまま送信されうる欠陥があった。

「アポ率0%」を計算していた分母（到達494件）は検証不能な推定値であり、
そもそも返信を記録する場所がシステムに存在しなかったため、
**返信が本当に無かったのか、記録していなかっただけなのかを区別できない。**

---

## 1. 送信結果の判定が誤っていた

### 症状
到達494件、失敗291件、要確認514件。

### 実態

| 記録 | 実態 |
|---|---|
| 到達 494 | うち **109件（22%）は画面が一度も変化していない** |
| 失敗 291 | 16社を調べて **15社は必須欄がすべて埋まっていた**（弾かれていない） |
| 要確認 514 | うち **241件（47%）はGoogle翻訳ウィジェット等を押していた** |

### 原因

**成功の誤判定** — 「ページ本文に成功文言がある」だけで成功にしていた。
「ありがとうございます」は問い合わせフォーム画面の常設挨拶として普通に出る。
さらに成功判定がエラー判定より先だったため、バリデーションで弾かれた画面も
成功になり得た。

**失敗の誤判定** — 「必須」という文字列をエラーの証拠にしていた。日本の
フォームは項目名の隣に「必須」バッジを常時表示する。

**押すボタンの誤り** — `extractButtons` がページ全体のボタンを可視性も出自も
見ずに集め、呼び出し側が「戻る/修正以外の最初の1つ」を押していた。実際に
押していたのは:

```
#cboxPrevious          … Colorbox ライトボックスの「前へ」
body > header > button … ハンバーガーメニュー
#goog-gt-thumbUpButton … Google 翻訳ウィジェットの高評価ボタン
郵便番号検索           … フォーム内のAJAX住所検索
修正する / リセット     … 押すと入力が消える
```

非表示要素の click は actionability を20秒待ってから必ず失敗する。

### 修正
- 判定基準を「成功文言があるか」→「**送信前から実際に変化した証拠があるか**」に変更。
  最も強い証拠は**入力した本文がページから消えたこと**。
- 確認画面での停止を検出。判定不能は `uncertain` に隔離。
- エラーは表示されているエラー要素（`.error` / `[role=alert]` 等）で判定。
- ボタン選択に可視性・フォーム内・否定語・disabled の判断を導入。
  押せる候補が無ければ「無い」と答える。

## 2. 本文が空のまま送信されうる欠陥（最も深刻）

`fillForm` は入力失敗を `log.warn` で握りつぶして先へ進んでいた。入力中に
フォームが再描画されればロケータは剥がれ、ブラウザが落ちれば途中までしか
入らない。**それでも送信ボタンは押される。**

相手には氏名とメールだけの空の問い合わせが届き、完了ページには遷移するので
L5は「成功」と記録 → 返信が来ないまま分母に入る。

**修正:** 送信前に本文欄の値をDOMから読み戻して検証。入っていなければ送らず
人へ回す。一度でも空文を送れば、その企業は抑制リストに載って二度と使えない。

---

## 3. 入力が遅くブラウザが落ちていた

本文1,050字を**1文字ずつ個別のPlaywright呼び出し**で打っていた。1通67秒。
e2eでは `Target crashed` を再現した。

**修正:** 48字チャンク化（キーイベントは1文字ずつ出す性質を維持）。
**67秒 → 17.6秒**。以前2回とも落ちていたe2eが完走するようになった。

## 4. 除外理由が実態を指していなかった

抑制リスト1,823社のうち `ineligible_form` が1,672社。

| 除外理由 | 実態 |
|---|---|
| `message_too_long` 158 | **102社は本文欄に maxlength が無い**。超過していたのは件名欄 |
| `unfillable_required` 638 | サイト内検索、「空のままにしてください」（罠）、辞書漏れの「名前」「FAX番号」 |
| `not_contactable` 317 | **75社は textarea を持っていた**（見出しが取れず `content` 等の name のみ） |
| `consumer_form` 142 | `会社見学`『工場見学』『ショールーム見学` はB2Bの問い合わせ種別 |

### 修正
- 件名は入力上限に合わせて詰める（氏名・会社名・メールは**絶対に詰めない** —
  嘘の値を送ることになる）。
- 本文以外の超過で送信を止めない。
- 入力上限が厳しいフォーム向けに短縮署名（81字）を用意。
- サイト内検索・hidden・「空のままに」を必須欄に数えない。
- 見出しの装飾（`*` `必須`）を落としてから比較。
- 辞書に `名前` と FAX を追加（FAXは必須指定のときだけ入力）。
- textarea は要素の種類で本文欄と判断。
- B2Bの「見学」を消費者向けの証拠にしない。

### 結果
**「非適格」で除外されている1,316社のうち352社が送信対象に戻せる。**

## 5. 測れる状態を作った

### 追加したもの

| コマンド | 用途 |
|---|---|
| `toiawase funnel` | 送信 → 到達 → 返信 → アポ を文面パターン別に集計 |
| `toiawase outcome <企業ID> <種別>` | 反応を手で記録 |
| `toiawase import-replies <path>` | 受信メール(.eml/CSV)から返信・アポを自動記録 |
| `toiawase experiment` | 文面A/Bの腕と割り当て状況 |
| `toiawase preflight` | 送信前の点検（問題があれば終了コード1） |
| `npx tsx scripts/requalify.ts` | 除外企業のうち今なら送れるものを再パース |
| `npx tsx scripts/diagnose_buttons.ts` | 送信ボタン選択の実ページ検証（送信しない） |
| `npx tsx scripts/diagnose_validation.ts` | 必須欄の充足状況（クリックもしない） |

### 送信結果の証拠
plan のスクリーンショットは2,256枚あったのに、**結果の証拠は0枚**だった。
送信直後の画面を `result_<id>.png` として保存し、可視テキストの冒頭とともに
`submissions` に記録するようにした。

### 文面A/B

| 腕 | 文字数 | 依頼 |
|---|---|---|
| `default`（対照） | 1,050字 | 3つ（返信 / 資料送付 / 日程調整） |
| `short` | 698字 | 1つ（日程調整リンクのみ） |

割り当ては企業IDから決定（乱数を使わない）。同じ企業は何度実行しても同じ
文面になるため、承認画面と送信内容が食い違わない。承認待ち873社で
48.7% / 51.3% に割れることを確認。

**なお、この実装中に `runExecute` が `templateName` を渡しておらず、
承認画面で見た文面と実際に送る文面が食い違っていたことも判明し、修正した。**

### 返信の自動記録で最も重要な点
日本企業の問い合わせフォームは**ほぼ必ず自動応答を返す**。これを返信として
数えると返信率は100%近くになり、文面を比べる意味が消える。
`Auto-Submitted` / `X-Autoreply` / `Precedence` ヘッダを最優先で判定する。

ただし「お問い合わせありがとうございます」単独では自動返信と決めつけない —
人が書いた返信の書き出しにも普通に出るため、これで切ると本物を捨ててしまう。

アポは「日程・打ち合わせ等の語＋月日の表記または予約通知」があるものだけ。
「検討させていただきます」をアポに数えると、この指標で改善を判断できなくなる。

## 次にやること

1. **`toiawase preflight`** で送信前の点検を通す。
2. **`npx tsx scripts/requalify.ts --apply`** で352社を送信対象に戻す
   （再パースは送信ではない。実際に送るには `plan` と承認が必要）。
3. 少数で送信し、`artifacts/result_*.png` を目視して判定が正しいか確かめる。
4. 受信した返信を **`toiawase import-replies`** で取り込む。
5. **`toiawase funnel`** で文面パターン別の返信率・アポ率を比較する。

**返信を記録しない限り、腕の比較は原理的に成立しない。** ここが埋まって
初めて「どの文面が効くか」を議論できる。

## 未検証のまま残っている論点

- 過去の送信1,340件には結果の証拠が無く、到達件数は検証できない。
- 送信は07:00〜11:00 JSTに集中している（1日の上限200件を午前中で使い切る）。
  時間帯がアポ率に効くかは未検証。
- 送信先は96%が一般問い合わせフォームで、宛先は総務・広報の可能性が高い。
  新卒採用の提案が人事に届いているかは未検証。
- 残る除外314社（`unfillable_required`）は209社が欠け1件のみで、
  内訳は長い尾になっている。個別対応の費用対効果は低い。
